language১. ANSI ম্যাপিং কী?
expand_more

আপনি যখন বাংলায় টাইপ করেন — যেমন "সালাম" — আপনার কম্পিউটার ইউনিকোড (Unicode) ব্যবহার করে। কিন্তু পুরনো অনেক ফন্ট (যেমন সোটনমিজে / বিজয়) ইউনিকোড বোঝে না। তারা ANSI এনকোডিং বোঝে।

এই JSON ফাইলটি হল সেই অনুবাদক — এটি বলে দেয় প্রতিটি ইউনিকোড বর্ণের জন্য কোন ANSI কোড ব্যবহার করতে হবে। যেমন:

স (ইউনিকোড) → #$A2 (ANSI কোড)
া (ইউনিকোড) → #$79 (ANSI কোড)
ল (ইউনিকোড) → #$0153 (ANSI কোড)
া (ইউনিকোড) → #$79 (ANSI কোড)
ম (ইউনিকোড) → #$203A (ANSI কোড)

ফলাফল: সালাম (ইউনিকোড) → ‡yv (ANSI সোটনমিজে)

account_tree২. JSON ফাইলের গঠন
expand_more

JSON ফাইলটি ৭টি প্রধান অংশে বিভক্ত:

{
  "Constants":           // বর্ণ ও গ্লিফের সংজ্ঞা
  "FullFormReplacements":   // পূর্ণ যুক্তাক্ষরের তালিকা
  "PreReplacements":     // আগাম প্রতিস্থাপন
  "PostReplacements":    // পশ্চাৎ প্রতিস্থাপন (সবার শেষে)
  "VowelRules":          // স্বরবর্ণের গ্লিফ নির্বাচনের নিয়ম
  "ConsonantGroups":     // ইউনিকোড ব্যঞ্জনবর্ণের গ্রুপ
  "AnsiGroups":          // ANSI কোডপয়েন্টের গ্রুপ (RaPhalas, Connectors)
}
Constants → ৭টি উপবিভাগ

Numbers (০-৯): অঙ্কের ANSI ম্যাপিং — "A_0": { "Value": "#$0030", "Comment": "০" }

VowelsAndKars: স্বরবর্ণ ও কারচিহ্ন — "A_AAKar": { "Value": "#$0079", "Comment": "া" }

Symbols: যতি ও প্রতীক — "A_Hasanta": { "Value": "#$E4", "Comment": "্" }

Consonants: ব্যঞ্জনবর্ণ — "A_K": { "Value": "#$201E#$FE", "Comment": "ক" }

FullForms: যুক্তাক্ষর — "A_K_K": { "Value": "#$45#$FE", "Comment": "ক্ক" }

FirstHalfForms: বর্ণের প্রথম খন্ড — "A_Reph": { "Value": "#$C5", "Comment": "র-এর রেফ" }

SecondHalfForms: বর্ণের দ্বিতীয় খন্ড — "A_ZFola": { "Value": "#$C4", "Comment": "য-ফলা" }

ConsonantGroups → ব্যঞ্জনবর্ণ গ্রুপ

ব্যঞ্জনবর্ণের গ্রুপিং — প্রতিটি গ্রুপের নামের অধীনে ইউনিকোড বর্ণের তালিকা। VowelRules-এ গ্রুপ নাম রেফারেন্স করা যায়।

"BaseLineRight": ["খ", "গ", "ঘ", "ন", "প", "ব", "ম", "ল", "স", "হ"]
AnsiGroups → ANSI কোডপয়েন্ট গ্রুপ

ANSI কোডপয়েন্টের গ্রুপিং — ConsonantGroups-এর মতোই, কিন্তু ইউনিকোড বর্ণের পরিবর্তে ANSI হেক্স কোড ব্যবহার হয়। VowelRules ও FinalTouch উভয় ক্ষেত্রেই ব্যবহার করা যায়।

"RaPhalas": ["#$C6", "#$C8", "#$C9", "#$CA", "#$CB", "#$CC"]
alt_route৩. কনভার্সন প্রক্রিয়া: ধাপে ধাপে
expand_more

ইউনিকোড থেকে ANSI-তে রূপান্তর একটি নির্দিষ্ট ক্রমে ঘটে। নিচে প্রতিটি ধাপ বর্ণনা করা হলো:

সালাম (ইউনিকোড)
    ↓
❶ FullFormReplacements
    ↓
❷ PreReplacements
    ↓
❸ ReplaceFullForms (FirstHalf + SecondHalf)
    ↓
❹ ReplaceKarsVowels (VowelRules দ্বারা)
    ↓
❺ PostReplacements (#{Var} সম্প্রসারণ)
    ↓
❻ FinalTouch (গ্লিফ পুনর্বিন্যাস + ANSI পরিশোধন)
    ↓
‡yv (ANSI আউটপুট)
❶ FullFormReplacements — বিস্তারিত

সবচেয়ে আগে চলে। যুক্তাক্ষর পুরো আকারে ANSI-তে রূপান্তরিত হয়। Key-গুলো দীর্ঘ থেকে ক্ষুদ্র ক্রমে সাজানো থাকে।

ন্ত্ব → #$67#$73#$FE
ন্ত   → #$68#$73#$FE
❷ PreReplacements — বিস্তারিত

ক্যারেক্টার প্রসেসিংয়ের আগে বিশেষ প্রতিস্থাপন। যেমন হসন্ত+দাঁড়ি → ব্যাকস্ল্যাশ।

্। → #$FF
❸ ReplaceFullForms — বিস্তারিত

FirstHalfForms ও SecondHalfForms ব্যবহার করে যুক্তাক্ষর তৈরি। যেমন র-এর রেফ + প = র্প।

❹ ReplaceKarsVowels — বিস্তারিত

সবচেয়ে জটিল ধাপ। কারচিহ্ন (ু, ূ, ৃ) বসানোর জন্য VowelRules ব্যবহার করে। নিচে বিস্তারিত দেখুন।

❺ PostReplacements — বিস্তারিত

সব গ্লিফ বসানোর পর অর্ডারিং ফিক্স। এখানে #{VariableName} ব্যবহার করা যায়।

"Key": "#$FE#{A_UKar1}", "Value": "#{A_UKar1}#$FE"
❻ FinalTouch — বিস্তারিত

সর্বশেষ ধাপে পুনর্বিন্যাস ও পরিষ্কারকরণ:

    হসন্ত, ZWJ, ZWNJ সরানো
    ApplyGenericGlyphSwaps — AnsiGroups থেকে মডিফায়ার (RaPhalas, Connectors) লোড করে প্রতিটি মডিফায়ার×প্রতি কার-এর জন্য modifier+kar → kar+modifier সুয়াপ
    লিগ্যাসি Default-ভার্সন কারেকশন (ট-কার, র-কার বিশেষケース)
rule৪. VowelRules: স্বরবর্ণের গ্লিফ নির্বাচন
expand_more

VowelRules নির্ধারণ করে — একটি কারচিহ্ন (ু, ূ, ৃ) কোন ব্যঞ্জনবর্ণের পরে বসলে কোন ANSI গ্লিফ ব্যবহার করবে।

JSON ফরম্যাট

"#$09C1": {                    // কী: ইউনিকোড উ-কার (U+09C1)
  "default": "#{A_UKar1}",    // ডিফল্ট মান (কোনো ম্যাপিং না মিললে)
  "mappings": [              // শর্তাধীন ম্যাপিং তালিকা (উপর থেকে নিচে চেক করে)
    {
      "consonants": "#$09B0",  // সরাসরি ইউনিকোড বর্ণ (র)
      "value": "#{A_UKar4}",   // কাঙ্ক্ষিত ANSI গ্লিফ
      "alt": "#{A_UKar2}"      // টগল চালু থাকলে এই মান ব্যবহার হয় (optional)
    },
    {
      "consonants": "BelowBaseVariant",  // ConsonantGroups নাম
      "value": "#$0024"
    },
    {
      "consonants": "RaPhalas",          // AnsiGroups নাম
      "value": "#{A_UKar2}"
    },
    {
      "consonants": "BaseLineRight",     // ConsonantGroups নাম
      "value": "#{A_UKar1}"
    }
  ]
}

কিভাবে ম্যাচিং হয় (Priority)

স্তর ১ — Direct Unicode Char: "consonants"-এর মান যদি একটি ইউনিকোড বর্ণ হয় (যেমন "#$09B0" বা "র"), তাহলে পূর্ববর্তী বর্ণের সাথে সরাসরি তুলনা করা হয়। মিললে value ব্যবহার হয়।

স্তর ২ — ConsonantGroups (Unicode): যদি "consonants" ConsonantGroups সেকশনের একটি গ্রুপের নাম হয় (যেমন "BaseLineRight", "BottomCenter"), তাহলে গ্রুপের তালিকায় পূর্ববর্তী বর্ণ আছে কিনা চেক করা হয়।

স্তর ৩ — AnsiGroups (ANSI): যদি গ্রুপটি AnsiGroups সেকশনে থাকে (যেমন "RaPhalas"), তাহলে ANSI কোডপয়েন্টের সাথে ম্যাচ করা হয়।

সর্বশেষ — Default: উপরের কোনোটাই না মিললে "default" মান ব্যবহার হয়।

alt (Toggle) ফিল্ড

alt ঐচ্ছিক। যখন টগল ON থাকে, value-এর পরিবর্তে alt ব্যবহার হয়। একই বর্ণের জন্য দুটি ভিন্ন ANSI গ্লিফের মধ্যে সুইচ করতে পারবেন।

বাস্তব উদাহরণ

রু (র + উ-কার): পূর্ববর্তী বর্ণ #$09B0 (র) — সরাসরি ম্যাচ (স্তর ১) → value = A_UKar4। টগল চালু থাকলে alt = A_UKar2।

টু (ট + উ-কার): 'ট' BelowBaseVariant গ্রুপে আছে (স্তর ২) → value = #$0024 (নিচে বসা উ-কার)।

ক্রু (ক্র + উ-কার): 'ক্র'-এর ANSI-তে র-ফলা #$C6 থাকে — RaPhalas গ্রুপে আছে (স্তর ৩) → value = A_UKar2।

গু (গ + উ-কার): 'গ' BaseLineRight গ্রুপে (স্তর ২) → A_UKar1 (সাধারণ উ-কার)।

ড়ু (ড় + উ-কার): 'ড়' কোনো গ্রুপেই নেই → default = A_UKar1।

❶ মূল সমস্যা: কেন এই গ্রুপিং প্রয়োজন?

বাংলা লেখার সময় ব্যঞ্জনবর্ণের নিচে যখন উ-কার (ু), ঊ-কার (ূ), ঋ-কার (ৃ) কিংবা র-ফলা (্র) বসে, তখন সব বর্ণের নিচে এগুলো একই রকম দেখায় না। বর্ণের নিচের অংশের আকৃতির ওপর ভিত্তি করে এদের আকৃতি ও বসার স্থান বদলে যায়। যেমন:

  • র + ু লিখলে হয় রু (এখানে উ-কারটি নিচে না বসে পাশে বসে)
  • ট + ্র + ু লিখলে হয় ট্রু (উ-কারটি র-ফলার সাথে লেগে নিচে বিশেষ আকৃতি নেয়)
  • গ + ু লিখলে হয় গু (ফন্টের সৌন্দর্য রক্ষায় উ-কারটি ঝুলে থাকে)

❷ VowelRules-এ ConsonantGroups-এর ব্যবহার

VowelRules-এর "consonants" ফিল্ডে ConsonantGroups-এর নাম উল্লেখ করলে ইঞ্জিন গ্রুপের তালিকা চেক করে:

"mappings": [
  {
    "consonants": "BelowBaseVariant",  // গ্রুপের নাম
    "value": "#$0024"                  // ট্র, ড্র, ঢ্র → বিশেষ উ-কার গ্লিফ
  },
  {
    "consonants": "RuClusters",        // গ্রুপের নাম
    "value": "#{A_UKar4}"             // গ্র, ত্র, দ্র → র-ফলার সাথে মানানসই উ-কার
  },
  {
    "consonants": "BaseLineRight",     // গ্রুপের নাম
    "value": "#{A_UKar1}"             // খ, গ, ঘ, প → সাধারণ ঝুলন্ত উ-কার
  }
]

ইঞ্জিন VowelRulesList লুপ করে → প্রতিটি Rule.Vowel ম্যাচ করে → Mappings-এ ConsonantGroupsMap.TryGetValue(Map.Consonants, GroupList) কল করে → GroupList.Contains(AConsonant) দিয়ে বর্ণটি গ্রুপে আছে কিনা চেক করে। ম্যাচ পেলে value ব্যবহার করে, না পেলে default।

❸ VowelRules-এ AnsiGroups-এর ব্যবহার (স্তর ৩)

যখন কোনো বর্ণ রূপান্তরের পরে ANSI-তে কনভার্ট হয়ে যায় (যেমন র-ফলা গ্লিফ #$C6), তখন ConsonantGroups (ইউনিকোড) দিয়ে ম্যাচ করা যায় না — কারণ ইউনিকোড বর্ণটি আর নেই। সেক্ষেত্রে AnsiGroups ব্যবহার করা হয়:

"mappings": [
  {
    "consonants": "RaPhalas",    // AnsiGroups নাম
    "value": "#{A_UKar2}"       // র-ফলার পরে ঝুলন্ত উ-কার
  }
]

ইঞ্জিন চেক করে: প্রথমে ConsonantGroupsMap-এ গ্রুপ খোঁজে → না পেলে AnsiGroupsMap-এ খোঁজে → AnsiGroupsMap.TryGetValue(Map.Consonants, GroupList) কল করে → ANSI কোডপয়েন্ট ম্যাচ করলে value ব্যবহার করে।

এর কারণেই BaseLineRight গ্রুপে শুধু বর্ণ ও যুক্তবর্ণ (র-ফলা ছাড়া) রাখতে হবে — র-ফলার পরে উ-কার বসালে AnsiGroups স্বয়ংক্রিয়ভাবে হ্যান্ডল করে।

❹ GetVowelGlyph — ভেতরে কী হয়?

VowelRules প্রক্রিয়াকরণের সময় GetVowelGlyph(AVowel, AConsonant, UseAlt) ফাংশনটি নিচের ধাপগুলো সম্পন্ন করে:

1. VowelRulesList = nil? → সরাসরি A_UKar1/A_UUKar1/A_RRIKar2 রিটার্ন করে (fallback)
2. VowelRulesList লুপ → Rule.Vowel = AVowel (যেমন #$09C1 = উ-কার) খোঁজে
3. প্রতিটি Mappings-এ:
   a. ConsonantGroupsMap-এ গ্রুপ খোঁজে → GroupList.Contains(AConsonant)
   b. না পেলে AnsiGroupsMap-এ গ্রুপ খোঁজে → GroupList.Contains(AConsonant)
   c. না পেলে সরাসরি Map.Consonants = AConsonant চেক (Direct char match)
   d. ম্যাচ পেলে UseAlt? → Map.AltValue : Map.Value
4. কোনোটাই না মিললে Rule.DefaultVal রিটার্ন

গুরুত্বপূর্ণ: ReplaceFullForms-এর পর চলে, তাই পূর্ববর্তী বর্ণ ANSI-তে কনভার্ট হয়ে যেতে পারে — ContainsBengaliChar চেক করে না পেলে fUniText (মূল ইউনিকোড) ব্যবহার করে পূর্ববর্তী বর্ণ বের করে।

ConsonantGroups হল ইউনিকোড ব্যঞ্জনবর্ণের একটি গ্রুপিং সিস্টেম। VowelRules-এ একটি গ্রুপের নাম উল্লেখ করলে, সেই গ্রুপের সব বর্ণের জন্য একই VowelRules প্রযোজ্য হয় — আলাদা আলাদা করে প্রতিটি বর্ণের জন্য mapping লিখতে হয় না।

JSON গঠন

"ConsonantGroups": {
  "BaseLineRight": [        // গ্রুপের নাম (VowelRules-এ রেফারেন্স)
    "খ", "গ", "ঘ",         // ইউনিকোড বর্ণ (সরাসরি অক্ষর)
    "চ", "ছ", "জ", "ঝ",
    "ণ", "থ", "ধ", "ন",
    "প", "ফ", "ব", "ম",
    "য", "ল", "ষ", "স",
    "ষ্ক", "স্ক", "স্প", "ম্প", "ম্ব", "ঙ্গ", "ন্স", "ল্গ", "প্স"
  ],
  "BottomCenter": [
    "ট", "ঠ", "ড", "ঢ",
    "ক্ট", "ন্ট", "ন্ড", "ল্ট", "স্ট"
  ],
  "SpecialLigatures": ["ক", "ত", "দ", "ভ", "শ", "হ"],
  "TraBasedLigatures": ["ন্ত", "স্ত", "ক্ত", "প্ত", "ত্ত"],
  "DraBasedLigatures": ["ন্দ", "ন্ধ", "দ্ভ", "ম্ভ"]
}

VowelRules-এ ব্যবহার

VowelRules-এর "consonants" ফিল্ডে গ্রুপের নাম দিন:

"mappings": [
  { "consonants": "BottomCenter", "value": "#{A_UKar2}" },   // ট, ঠ, ড, ঢ → A_UKar2
  { "consonants": "BaseLineRight", "value": "#{A_UKar1}" }   // খ, গ, ঘ, ... → A_UKar1
]

গ্রুপ না থাকলে কী হয়?

JSON ফাইলে ConsonantGroups সেকশন না থাকলেও ইঞ্জিন স্বয়ংক্রিয়ভাবে BaseLineRight গ্রুপ তৈরি করে (InitializeDefaultConsonantGroups ফাংশনের মাধ্যমে)। আপনি চাইলে এই গ্রুপটি ওভাররাইড করতে পারেন। অন্যান্য গ্রুপ শুধু তখনই কাজ করবে যখন আপনি সেগুলো JSON-এ সংজ্ঞায়িত করবেন।

কেন ConsonantGroups ব্যবহার করবেন?

    পুনরাবৃত্তি কমায় — ২০টি বর্ণের জন্য ২০টি mapping লেখার বদলে ১টি গ্রুপ mapping
    কেন্দ্রীয় নিয়ন্ত্রণ — এক জায়গায় বর্ণ যোগ/বাদ দিন, সব VowelRules আপডেট হবে
    পড়তে সহজ — "BaseLineRight" বোঝা সহজ, ২০টি আলাদা বর্ণের চেয়ে

❶ ব্যঞ্জনবর্ণের ৩টি দল

বর্ণগুলোর নিচের অংশের ডিজাইনের ওপর ভিত্তি করে এদের ৩টি দলে ভাগ করা হয়েছে:

BelowBaseVariant — নিচের অংশ গোল বা সোজা

যেসব বর্ণের নিচে সাধারণ র-ফলা ঝুলে না থেকে সোজা বা ছাতার মতো বসে। যেমন: ট্র, ড্র, ঢ্র (এবং যুক্তবর্ণ যেমন ণ্ট্র, ণ্ড্র, ষ্ট্র)।

কেন আলাদা: এদের নিচে উ-কার দিলে সেটি সাধারণ উ-কারের মতো না হয়ে ফন্টের ভেতরে থাকা একটি বিশেষ গ্লিফ (যেমন #$0024 বা $) ব্যবহার করতে হয়।

RuClusters — র-ফলা যুক্ত ক্লাস্টার

যেসব বর্ণের সাথে র-ফলা যুক্ত হওয়ার পর তারা দেখতে অনেকটা 'র' বর্ণের মতো আচরণ করে। যেমন: গ্র, ঘ্র, ত্র, দ্র ইত্যাদি।

কেন আলাদা: এদের নিচে যখন উ-কার (ু) বসে, তখন সেটি যেন র-ফলার সাথে সংঘর্ষ (clash) না করে, সেজন্য বিশেষ উ-কার (যেমন A_UKar4 বা A_UKar3) ব্যবহার করা হয়।

BaseLineRight — ডানপাশে খাড়া দাগ বা স্টেম যুক্ত বর্ণ

যেসব বর্ণের ডানপাশে খাড়া টান আছে এবং নিচে ডান কোণায় র-ফলা বা উ-কার বসে। যেমন: খ, গ, ঘ, ণ, থ, দ, ধ, ন, প ইত্যাদি এবং এদের দিয়ে তৈরি যুক্তবর্ণ।

কেন আলাদা: এদের নিচে সাধারণ ঝুলন্ত উ-কার (A_UKar1) বসে।

❷ একক ব্যঞ্জনবর্ণ + র-ফলা — গ্রুপিং গাইড

একক ব্যঞ্জনবর্ণের সাথে র-ফলা যুক্ত হলে সেগুলোকে নিচের গ্রুপে বসাতে হবে:

BelowBaseVariant গ্রুপে যাবে (নিচের অংশ গোল):

"ট্র", "ড্র", "ঢ্র"

RuClusters গ্রুপে যাবে বাকি সবগুলো (র-ফলা ক্লাস্টার):

"ক্র", "খ্র", "গ্র", "ঘ্র", "চ্র", "ছ্র", "জ্র", "ঝ্র",
"ত্র", "থ্র", "দ্র", "ধ্র", "ন্র", "প্র", "ফ্র", "ব্র",
"ভ্র", "ম্র", "য্র", "ল্র", "শ্র", "ষ্র", "স্র", "হ্র", "ড়্র", "ঢ়্র"

❸ যুক্তবর্ণ + র-ফলা — গ্রুপিং গাইড

যুক্তবর্ণের সাথে র-ফলা (তিন-বর্ণের ক্লাস্টার) — এদের শেষ বর্ণের আকৃতির ওপর ভিত্তি করে গ্রুপিং:

BelowBaseVariant গ্রুপে যাবে (শেষে ট/ড থাকায় নিচের অংশ গোল):

"ক্ট্র", "ণ্ট্র", "ণ্ড্র", "প্ট্র", "ষ্ট্র"

RuClusters গ্রুপে যাবে বাকি যুক্তবর্ণগুলো (শেষে খাড়া টান বা র-ফলা):

"ক্ত্র", "ক্ষ্র", "ন্ত্র", "ন্দ্র", "ম্প্র", "স্ক্র"

❹ টেবিল — কনফিগারেশন ফাইলে বসানোর নিয়ম

গ্রুপের নাম কিভাবে বসাবেন? উদাহরণ
BelowBaseVariant র-ফলাসহ "ট্র", "ড্র", "ণ্ট্র", "ষ্ট্র"
RuClusters র-ফলাসহ "গ্র", "ত্র", "দ্র", "ধ্র"
BaseLineRight শুধু বর্ণ/যুক্তবর্ণ (র-ফলা ছাড়া) "খ", "গ", "স্ক", "স্প"

❺ কেন এই নিয়ম?

BelowBaseVariant এবং RuClusters গ্রুপে র-ফলাসহ বর্ণ বসানোর কারণ: র-ফলা বসার পর উ-কার বা ঊ-কারের রূপ সম্পূর্ণ বদলে যায়। ইঞ্জিনকে চেনানোর জন্য এদের র-ফলাসহ লিখতে হয়।

অন্যদিকে, BaseLineRight গ্রুপে শুধু বর্ণ ও যুক্তবর্ণ (র-ফলা ছাড়া) বসে। কারণ:

"খু" → উ-কারের আগে "খ" → BaseLineRight → সাধারণ ঝুলন্ত উ-কার ✓
"খ্রু" → কনভার্টার আগে র-ফলা ANSI গ্লিফে রূপান্তর করে
       → উ-কারের আগে #$C6 (র-ফলা) → AnsiGroups.RaPhalas ডিটেক্ট করে
       → ঝুলন্ত উ-কার (A_UKar2) স্বয়ংক্রিয়ভাবে বসে ✓
       → BaseLineRight-এ "খ্র" লেখার প্রয়োজন নেই!

AnsiGroups-এর RaPhalas নিয়মের কারণে ইঞ্জিন স্বয়ংক্রিয়ভাবেই বুঝতে পারে যে র-ফলার পর কোন উ-কার বসাতে হবে। তাই BaseLineRight গ্রুপে র-ফলাসহ বর্ণ বসানোর দরকার নেই।

group_work৬. AnsiGroups: ANSI কোডপয়েন্ট গ্রুপিং
expand_more
ConsonantGroups vs AnsiGroups: ConsonantGroups ইউনিকোড বর্ণ গ্রুপ করে — VowelRules-এ "BottomCenter" রেফারেন্স করলে 'ট', 'ঠ', 'ড', 'ঢ'-এর সাথে ম্যাচ করে। AnsiGroups ANSI কোডপয়েন্ট গ্রুপ করে — রূপান্তরের পরে কাজ করে, যখন টেক্সট ইতিমধ্যে ANSI-তে কনভার্ট হয়ে গেছে।

JSON গঠন

"AnsiGroups": {
  "RaPhalas": ["#$C6", "#$C8", "#$C9", "#$CA", "#$CB", "#$CC"],
  "Connectors": ["#$FE", "#$E9"]
}

দুই জায়গায় ব্যবহার হয়

১. VowelRules-এ (স্তর ৩ ম্যাচিং):

উদাহরণ: "consonants": "RaPhalas" — পূর্ববর্তী বর্ণ ANSI-তে কনভার্ট হওয়ার পর যদি র-ফলা (যেমন #$C6) থাকে, তাহলে ম্যাচ করবে।

ক্র + ু  →  প্রক্রিয়ায়: ক + ্ + র-ফলা(#$C6) + উ-কার
→ GetVowelGlyph: পূর্ববর্তী ANSI = #$C6 → RaPhalas গ্রুপে আছে → A_UKar2

২. FinalTouch-এ (ApplyGenericGlyphSwaps):

সব গ্লিফ বসানোর পর, মডিফায়ার (RaPhalas, Connectors) কার-এর (ু/ূ/ৃ) আগে থাকলে অর্ডার সুয়াপ করে:

আগে: র-ফলা(#$C6) + উ-কার(#$25)  →  পরে: উ-কার(#$25) + র-ফলা(#$C6)

গ্রুপগুলো কী কী?

RaPhalas — র-ফলা সম্পর্কিত ANSI কোডপয়েন্ট:

  • #$C6 — র-ফলা ১
  • #$C8 — ম-ফলা
  • #$C9 — ন-ফলা
  • #$CA — ল-ফলা
  • #$CB — স-ফলা
  • #$CC — হ-মি

Connectors — যুক্তি সেতু হিসেবে কাজ করে এমন কোডপয়েন্ট:

  • #$FE — হসন্ত (যুক্তি সেতু)
  • #$E9 — ে + া (ক্ষিণ)

ApplyGenericGlyphSwaps — ডায়নামিক পুনর্বিন্যাস

FinalTouch শেষ ধাপে ApplyGenericGlyphSwaps ফাংশন চলে:

১. সব কার গ্লিফ কালেক্ট করে: A_UKar1-4, A_UUKar1-3, A_RRIKar1-2
২. AnsiGroups থেকে মডিফায়ার লোড করে (RaPhalas + Connectors)
৩. ফলব্যাক: JSON-এ AnsiGroups না থাকলে RFola, ZFola, Reph, RR, R, RRH
৪. Nested loop: প্রতিটি মডিফায়ার × প্রতিটি কার
৫. ReplaceStr(Modif + Kar, Kar + Modif) — অর্ডার সুয়াপ

এর ফলে ৩৩টির বেশি হার্ডকোডেড ReplaceStr লাইনের প্রয়োজন হয় না — শুধু গ্রুপে নতুন কোডপয়েন্ট যোগ করলেই স্বয়ংক্রিয়ভাবে নতুন কম্বিনেশন হ্যান্ডল হয়।

❶ RaPhalas গ্রুপ — র-ফলা চেনার জন্য

অ্যানসি ফন্টে র-ফলার বিভিন্ন রূপের জন্য আলাদা আলাদা কোড থাকে (যেমন র-ফলা ১, র-ফলা ২ ইত্যাদি)। ইঞ্জিন যেন বুঝতে পারে এগুলো সব র-ফলা, তাই এদের এক গ্রুপে রাখা হয়েছে:

"RaPhalas": ["#$C6", "#$C8", "#$C9", "#$CA", "#$CB", "#$CC"]
  • #$C6 — র-ফলা ১
  • #$C8 — ম-ফলা
  • #$C9 — ন-ফলা
  • #$CA — ল-ফলা
  • #$CB — স-ফলা
  • #$CC — হ-মি

VowelRules-এ "consonants": "RaPhalas" রেফারেন্স করলে — পূর্ববর্তী ANSI কোড RaPhalas গ্রুপে আছে কিনা চেক করে। FinalTouch-এ ApplyGenericGlyphSwaps RaPhalas গ্রুপ থেকে মডিফায়ার লোড করে কার অর্ডার সুয়াপ করে।

❷ Connectors গ্রুপ — যুক্তবর্ণের সেতু

যুক্তবর্ণ তৈরি করার জন্য ফন্টের ভেতরে যে সংযোগকারী গ্লিফগুলো ব্যবহার হয়:

"Connectors": ["#$FE", "#$E9"]
  • #$FE — হসন্ত (যুক্তি সেতু)
  • #$E9 — ে + া (ক্ষিণ)

ApplyGenericGlyphSwaps-এ Connectors গ্রুপ থেকেও মডিফায়ার লোড হয় — কার-এর সাথে অর্ডার সুয়াপ করার জন্য।

❸ কেন AnsiGroups আলাদা?

ConsonantGroups ইউনিকোড বর্ণ গ্রুপ করে — কনভার্টের আগে কাজ করে। AnsiGroups ANSI কোডপয়েন্ট গ্রুপ করে — কনভার্টের পরে কাজ করে, যখন টেক্সট ইতিমধ্যে ANSI-তে কনভার্ট হয়ে গেছে।

VowelRules উভয়কেই ব্যবহার করতে পারে:

  • স্তর ২ (ConsonantGroups): পূর্ববর্তী বর্ণ ইউনিকোডে থাকলে — যেমন "গ" + উ-কার → "গু"
  • স্তর ৩ (AnsiGroups): পূর্ববর্তী বর্ণ ANSI-তে কনভার্ট হয়ে গেলে — যেমন র-ফলা #$C6 + উ-কার

এই দ্বৈত পদ্ধতির কারণেই BaseLineRight গ্রুপে র-ফলা ছাড়া বর্ণ রাখা যায় — AnsiGroups স্বয়ংক্রিয়ভাবে র-ফলা+উ-কার হ্যান্ডল করে।

ExpandVarRefs

ইনপুট স্ট্রিং-এ #{VarName} প্যাটার্ন খুঁজে Constants থেকে মান এনে বসায়।

লজিক: Pos('#{') → PosEx('}') → AnsiRegistryMap খুঁজে → মান বসায় → আবার খোঁজে

ResolveStringValue

ExpandVarRefs + ProcessHexAndUnicode একসাথে করে।

"#$FE#{A_UKar1}" → ExpandVarRefs → "#$FE#$25" → ProcessHexAndUnicode → দুটি ক্যারেক্টার

GetVowelGlyph

3-স্তরের ম্যাচিং প্রায়োরিটি: mappings-এ Direct Unicode Char → ConsonantGroups → AnsiGroups → default। টগল চালু থাকলে alt মান ব্যবহার করে।

VowelRulesList লুপ → Rule.Vowel = AVowel খোঁজে → Mappings লুপ → GroupList.Contains বা সরাসরি তুলনা → ম্যাচ পেলে Exit(Value/AltValue)

ApplyGenericGlyphSwaps

ANSI আউটপুটে মডিফায়ার+কার অর্ডার ঠিক করে। AnsiGroups থেকে মডিফায়ার লোড করে, সব কারের সাথে Nested loop চালিয়ে ReplaceStr(Modif+Kar, Kar+Modif) করে।

RaPhalas + Connectors → Modifiers List → UKar1-4 + UUKar1-3 + RRIKar1-2 → Kars List → for Modif in Modifiers do for Kar in Kars do ReplaceStr(Modif+Kar, Kar+Modif)

BaseLineRightCharacter

ব্যঞ্জনবর্ণ বেসলাইনে বসে কিনা পরীক্ষা করে। বেসলাইনে বসা বর্ণ: খ, গ, ঘ, ণ, থ, দ, ধ, ন, প, ব, ম, য, র, ল, শ, ষ, স, হ, য়।

ReplaceKarsVowels

উ-কার, ঊ-কার, ঋ-কার প্রক্রিয়া করে। Pos দিয়ে কার খুঁজে → পূর্ববর্তী ক্যারেক্টার বের করে → GetVowelGlyph ডাকে → WideStuffString দিয়ে প্রতিস্থাপন করে। গুরুত্বপূর্ণ: ReplaceFullForms-এর পর চলে, তাই পূর্ববর্তী বর্ণ ANSI-তে কনভার্ট হয়ে যেতে পারে — ContainsBengaliChar চেক করে না পেলে fUniText (মূল ইউনিকোড) ব্যবহার করে।

FinalTouch

সর্বশেষ ধাপ: হসন্ত গ্লিফ ফিক্স, ApplyGenericGlyphSwaps (AnsiGroups থেকে মডিফায়ার লোড করে কার অর্ডার ঠিক করে), লিগ্যাসি Default-ভার্সন কারেকশন, ANSI পরিশোধন (শুধু 0x00-0xFF) রাখে।

ক্র = ক + ্ + র-ফলা। ধাপে ধাপে ক্রু (ক্র+উ-কার) কিভাবে ANSI-তে রূপান্তরিত হয়:

❶ শুরু: ইনপুট = ক (ক) + ্ (হসন্ত) + র (র) + ু (উ-কার)

❷ FullFormReplacements: ক্র (ক্র) এর এন্ট্রি নেই → skip

❸ ReplaceFullForms: ক + ্ + র → ক + র-ফলা (র-এর দ্বিতীয় খন্ড)

❹ ReplaceKarsVowels: পূর্ববর্তী বর্ণ = র-ফলা (#$C6) → GetVowelGlyph ডাকে

❺ GetVowelGlyph ম্যাচিং: ু (উ-কার) এর VowelRules-এ:

Direct char match? #$C6 নয় → No
ConsonantGroups? "RaPhalas" গ্রুপ নেই → No
AnsiGroups? "RaPhalas"-এ #$C6 আছে → Yes → value = A_UKar2

❻ ফলাফল: ক + র-ফলা(#$C6) + উ-কার(A_UKar2 = #$25)

❼ FinalTouch ApplyGenericGlyphSwaps: র-ফলা(#$C6) + উ-কার(#$25) → উ-কার(#$25) + র-ফলা(#$C6)

শেষ ফলাফল: ক + #$25 + #$C6 = ক্রু (ANSI)
